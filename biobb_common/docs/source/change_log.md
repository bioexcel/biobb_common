# Biobb_common ChangeLog

## What's new in version [5.3.3](https://github.com/bioexcel/biobb_common/releases/tag/v5.3.3)?

* [FEATURE] Provenance of workflows run on several machines (ie: setup on a laptop, MD on a cluster): one execution environment per machine, `biobb_provenance merge --path-map OLD=NEW` and checksum linking of the steps run elsewhere. Graphs, preview and README color the steps by machine.
* [FEATURE] New `provenance_user_host` property (default `True`): record the hostname, the username and the SLURM node list in the execution environment. Disable it or review the crate before publishing it.
* [FEATURE] Provenance records the parameters of GROMACS mdp and AMBER namelist files (input files, or the ones generated by the block, ie: `grompp.mdp`).
* [FEATURE] Steps skipped by the `restart` property without a previous crate are recorded without start time (end time = last modification of the outputs), so the provenance of a workflow re-run only to record it does not claim the simulations ran instantly.
* [FIX] Provenance records the documented file arguments that blocks keep outside `io_dict` (ie: the topology zip of `grompp`, `genion` and `solvate`).
* [FIX] `workflow_provenance` no longer fails when the workflow script is read from stdin (`python - < workflow.py`).
* [UPDATE] Provenance documentation: GROMACS MD setup workflow example.

## What's new in version [5.3.2](https://github.com/bioexcel/biobb_common/releases/tag/v5.3.2)?

* [FEATURE] Block and workflow [provenance](https://biobb-common.readthedocs.io/en/latest/provenance.html) as RO-Crates: `provenance` and `provenance_path` properties, `workflow_provenance` context manager and `biobb_provenance` command line tool to merge, draw and validate the crates.
* [UPDATE] New dependency: `rocrate`. Optional: `graphviz` (`pip install biobb_common[graph]` or `conda install python-graphviz`) to draw the provenance graphs as images.
* [FEATURE] New `raise_error` property: raise a `subprocess.CalledProcessError` if the command exits with a non-zero code instead of only setting `return_code`.
* [FIX] `launchlogger` closes the step log files also when the block raises an exception.
* [FEATURE] The `equal` test fixture compares CSV and TSV files.
* [FEATURE] New `raises` test fixture to assert that a block raises an exception.
* [FEATURE] `ConfReader` checks the configuration file structure and reports invalid first-level keys.
* [UPDATE] Improved log messages.
